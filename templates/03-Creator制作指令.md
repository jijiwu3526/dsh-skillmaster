# 交给 DSH Creator（创造模式）的指令

以下附上已确认的《工作用途与预设规格》。请在**当前 DSH 安装版本**里创建一个新的会话级 Agent Preset，ID、显示名、描述与行为以规格为准；以当前 Web `standard` Preset 为基线，仅按能力清单增减子插件，保留运行所需的基础设施。不要覆盖内置 `standard`。将角色、工作流程和交付标准放在该 Preset 的 persona/提示词配置中，避免把访谈的整个聊天历史复制到系统提示词。

工作步骤：

1. 读取当前安装的 DSH Preset 格式和 Web profile。0.1.7 及以后的声明式 Preset 应由 profile/bundle 中的 `@deepseek-ai/dsh-agent-preset` 行管理；旧版本才使用 `$DSH_HOME/.agent-presets/<id>/agent.cordis.yml`。不要混用格式。
2. 先写一份变更设计稿：所选基线、每个子插件的用途、权限、persona 文本、持久资料路径、配置位置与回退方式。
3. 使用 DSH 自带的 Creator 插件/预设管理能力写入配置。只让需要的工具进入会话。对第三方模块记录来源、版本和许可证；如需安装，先检查它是否已在 profile 中可用。
4. 列出当前 Preset 名单和健康状态，确认新 ID 唯一且可用。在设置页面将这个 Preset **设为默认**；若当前 Creator 无权限改默认，请明确列出需要我在“设置 → Agent 预设”点击的具体项。
5. 创建一个测试会话，用 3 个正例、2 个边界例验证：预设 ID、实际工具、系统提示、输出结构与文件范围。不要把测试会话当作正式工作会话。
6. 把最终的配置、依赖和测试结果整理为 Markdown，附在项目目录；不要在文档中写 API Key、Cookie 或含 token 的启动 URL。

请先核对《工作用途与预设规格》里所有“待确认”项，任何影响权限或实际业务行为的空项都要向我询问。完成后告诉我最终的 Preset ID；Python 创建器会直接使用它。
