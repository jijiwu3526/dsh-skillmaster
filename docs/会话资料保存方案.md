# 会话资料保存方案

## 每次定制时保存什么

在规划会话结束时保存完整的原始 DSH 导出 ZIP，以及人可读的规格 Markdown。规格至少记录用途、输入输出、授权范围、语言风格、成功标准、反例、确认时间和版本；导出 ZIP 记录当时的对话证据。Creator 完成后，再保存最终 Preset 配置、所用插件及版本、默认项选择、测试样例和结果。

建议目录：

```text
my-work-assistant/
  brief.md                 # 确认后的用途规格
  decisions.md             # 关键决定和取舍
  preset/                  # Creator 实际写出的当前版本配置
  tests/acceptance.md      # 3 个正例与 2 个边界例
  records/
    planning-session.zip   # 规划会话原始导出
    creator-session.zip    # Creator 会话原始导出
    session-....json        # 创建回执
    work-session.zip       # 正式工作原始导出
```

`dsh_session.py export` 使用 DSH 的原始会话导出端点，保留日志、下属会话和相关媒体附件。它不把事件重新拼接成 Markdown，因为重新拼接可能丢掉工具参数、时间、事件关系或非文本内容。若需阅读版，另行从原始导出生成摘要，并始终保留原件。

## 资料界限

- 把已确认且稳定的规则写进 Preset；不断变化的项目事实放进项目文件，由新会话按需读取。
- 不把规划会话的猜想、未经确认的结论、API Key 或含 token 的地址写进 persona。
- `records/` 可能含用户输入、工具输出和附件，分享前逐项审查。Cookie 缓存位于用户主目录，不应放进项目 ZIP。
- 一次配置调整后更新 `brief.md` 与 `decisions.md`，记录新旧 Preset ID、配置版本、变更理由及测试结果。

## 记忆文件（`memory.json`）的留存与脱敏

`dshstudio` 把「每个预设实际提供什么工具」和「你习惯用哪个」记在
`~/.config/dsh-conversation-studio/memory.json`（权限 `0600`）。

**它记了什么**

| 字段 | 内容 | 是否敏感 |
| --- | --- | --- |
| `profiles[].tools` | 工具名清单 | 否 |
| `profiles[].cwd` | 会话工作目录的**绝对路径** | **是**——含用户名与目录结构 |
| `profiles[].notes` | 你写的场景描述 | 可能 |
| `profiles[].source_zip` | 来源归档路径 | 低 |
| `preferences[].cwd` | 项目绝对路径 | **是** |
| `preferences[].scenario` | 场景描述 | 可能 |
| `incidents[].detail` | 故障细节 | 可能含路径 |

**结论：这个文件可以泄露你的本机目录结构。** 它不含对话内容，也不含 token
（token 只存在于 `cookies.txt`），但绝对路径本身就是信息。

**分享前请做**

1. 删掉或替换 `cwd` 字段——路径是最没必要留的部分。
2. 检查 `notes` 与 `scenario` 是否写了不该外传的项目名。
3. 不要把 `memory.json` 和 `cookies.txt` 一起打包。**`cookies.txt` 里是有效会话凭证，
   泄露等于让别人能连你的本机 DSH。**

**与项目资料的关系**

记忆是**跨项目共享的全局数据**。项目特有的决策仍应留在项目目录：

| 内容 | 放哪 |
| --- | --- |
| 这个项目该用哪个预设 | 项目 `brief.md`（可版本化、可评审） |
| 各预设分别有什么工具 | `memory.json`（工具会随 DSH 升级变化，不适合写死进项目文档） |
| 某次为什么换预设 | 项目 `decisions.md` |

理由：工具清单随 DSH 版本变，写进项目文档会过期；写进 `memory.json` 则每次
`observe` 都会更新，并记录 `tools_changed_at` 便于发现漂移。

**预设配置本身要单独留档。** `~/.dsh/.agent-presets/<id>/agent.cordis.yml`
不在记忆里，也没有备份。删掉就永久丢失。装好后应复制到项目仓库：

```
my-work-assistant/
  preset/
    review-focused/
      agent.cordis.yml   # Creator 或人工写出的当前版本配置
      preset.yml
```

## 恢复路线

若新的 Preset 无法挂载，先从 DSH 设置页把默认值切回健康的内置预设；随后检查 Creator 保存的配置和插件依赖。已有会话可能锁定其创建时的预设，修复默认项不会自动改变旧会话。保留原始导出与配置版本，以便分析和回滚。

排障顺序建议：

1. `python3 -m dshstudio.cli list --detail` 看记忆里各预设的画像。
2. 直接读 roster 的 `broken` 字段——它是挂载失败的一手原因。
3. 若 `broken` 为空但 `session/create` 仍失败，看错误里的**文件路径 + 字段名**，
   那类错误比 `broken` 更精确。
4. 用 `python3 -m dshstudio.cli incident <preset> "<现象>"` 把现象记下来，
   下次遇到同类问题记忆里能查到。
