## 第二轮：缺陷修复

首版 401 处理有缺陷：只要本机缓存中已有任何 Cookie，脚本就不再用启动 URL 里的 token 重新认证，
而错误提示却建议用户「传入含 `?token=` 的完整 URL」——该建议在这种情况下无效，用户会陷入
反复 401 的循环。

| 缺陷 | 修复 | 回归用例 |
| --- | --- | --- |
| 死循环 | 收到 401 时清空缓存、重换一次 token（**只重试一次**） | `test_stale_cookie_reauthenticates_from_token_url` |
| 缓存损坏 | 读前判空 + 捕获 `LoadError` | `test_corrupt_cookie_file_is_tolerated` |
| 矛盾参数 | `--workspace-id` 与 `--register-workspace` 并存时拒绝 | `test_workspace_id_rejects_register_workspace` |

> 修复 1 有个约束：不能在每次带 token 时都强制重新认证，那会让原有用例的
> `token_hits == 1` 断言失败。正确做法是**仅在 401 时重试**。
> 三个新用例在原代码上确实失败，是有效的守门测试。

### 权威工具清单的发现

会话导出里的 `request/header` 事件携带 **DSH 发给模型的真实工具清单**。实测三个预设：

| 预设 | 权威工具数 | 模型自述 | 差值原因 |
| --- | --- | --- | --- |
| `minimal` | **1** | 13 | 宿主注入的 `mcp__*` 插件 |
| `standard` | **28** | 40 | 同上 |
| `review-focused` | **24** | 36 | 同上 |

早前版本靠「问模型你有哪些工具」来判断，因格式漂移而不可靠（同一预设三次测量得到
13 / 2 / 0 三种结果）。改用 `request/header` 后问题消失。

由此还确认了一条边界：**`mcp__computer_use__*` 与 `mcp__node_repl__js` 不在任何预设的
权威清单里**——它们由宿主 profile 注入，预设裁剪不到。
